# Работа с проектом

Roblox-игра. Код — `src/` (Luau; UI на React Luau + ReactRoblox, анимация UI — Ripple). Studio — через Roblox Studio MCP. Синхронизация исходников — Rojo. Глобальные ассеты — `C:\Users\dakem\Documents\RobloxGames\Assets`, ассеты игры — `assets/`.

## Перед задачей

1. Прочитай `docs/README.md` и только документы изменяемой системы. UI или ввод — `docs/ui.md`; инвентарь — также `docs/inventory.md`.
2. Найди инварианты (`UI-01`, `INV-03`, `GP-02` …), которые задевает задача. Назови их до правки.
3. `docs/history/` не читай без запроса: это журнал прошлых работ, а не правила.

## Границы изменений

- Меняй только то, что требует задача. Не переписывай и не «улучшай» соседние функции, маршруты окон, тайминги, формулы и баланс.
- Если для задачи нужно изменить поведение вне её рамок или нарушить инвариант — остановись и спроси пользователя.
- При расхождении кода и инварианта исправляй код. Инвариант меняется только по прямому запросу пользователя, в той же задаче.

## Rojo и MCP

- Скрипты меняй только файлами в `src/`. В Studio их доставляет `rojo serve default.project.json --address 127.0.0.1`. Не записывай Source скриптов через MCP.
- Добавил mapping в `*.project.json` — перезапусти `rojo serve`. Не копируй модуль в Studio через MCP вместо этого.
- MCP: чтение дерева, Play-проверки, консоль, правки сцены, карты и ассетов. Изменения карты для release экспортируй (см. `docs/development.md`).
- Окна UI из Figma пользователь импортирует плагином FigBlox; они живут только в Studio в `ReplicatedStorage.UITemplates` (см. `docs/ui.md`). Код их клонирует и заполняет; в `src/` и файлы их не переносить, внешний вид не перестраивать кодом.
- Не создавай временные файлы и папки в `src/` и `Packages/`: Rojo падает на удалённых путях. Временные файлы — в `.tools/`.
- После проверки удали временные объекты Studio и останови Play. StudioMode=Mock включай только временно в сцене, не в `src/server/data/Config.luau`.

## Не трогать

- `.tools/` — локальные бэкапы и сборки, не источник правды.
- `Packages/` — зависимости Wally; `src/serverPackages/ProfileStore.luau` — сторонняя библиотека.
- `*.rbxlx`, `ShopUIBundle.rbxmx`, `assets/**/exports/*.rbxmx` — генерируются Rojo или скриптами из `tools/`; руками не правятся.

## Перед «готово»

1. `stylua src`, затем `selene src` — без новых ошибок (baseline: 2 ошибки, 18 предупреждений).
2. `rojo build default.project.json -o .tools/check.rbxlx` проходит.
3. Сценарии задетых инвариантов и подходящие автопроверки из `docs/verification.md` выполнены через MCP, если Studio доступна.
4. Документация обновлена в той же задаче по правилам ниже.
5. В ответе: что проверено, каким методом, что не проверено.

## Документация

- `docs/` описывает текущее поведение и правила, а не историю.
- Поведение изменилось — перепиши абзац или инвариант на месте. Не добавляй разделы «Изменения от <даты>».
- Результаты проверок не пиши в документы систем. Обнови строку в таблице статуса `docs/verification.md`; подробности — в ответ пользователю и сообщение коммита.
- Новый инвариант добавляй, только когда пользователь утвердил правило. Формат: `ID — правило (утверждено ГГГГ-ММ-ДД)`.
- Документ не длиннее 15 000 символов. Перерос — сожми или раздели, не дописывай.
- Отделяй реализованное от планов.
