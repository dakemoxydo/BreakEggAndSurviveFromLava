## Как поддерживать источник истины

1. Перед изменением механики прочитать соответствующие документы.
   Перед изменением UI или ввода обязательно прочитать [ui.md](ui.md); маршруты окон являются контрактом проекта.
2. В одной задаче обновлять исходники и документацию: правило, численные значения, API и способ проверки.
3. Реализованное поведение описывать утвердительно. Предложения обозначать как планы и не включать в перечень работающих функций.
4. При расхождении документации и кода проверить реализацию, исправить расхождение и записать ограничения. Само описание не означает, что функция реализована или протестирована.
5. Баланс хранить в конфигурациях Luau; [balance.md](balance.md) содержит их документированное представление. Не поддерживать независимую таблицу цен в UI.
6. Результаты проверок указывать с датой и методом. Старые результаты не считать повторной проверкой после изменений.
7. Корневой README использовать как точку входа. Спецификацию развивать здесь; манифесты ассетов остаются техническим учётом файлов и Roblox ID.
