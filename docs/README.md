## Как вести документацию

1. Описывай текущее поведение утвердительно. Изменилось поведение — перепиши абзац на месте; не добавляй разделы «Изменения от <даты>».
2. Инварианты (`UI-01`, `INV-02`, `GP-03`, `SAVE-01`) — правила, которые нельзя нарушать попутно. Новый инвариант — только по утверждению пользователя: `ID — правило (утверждено ГГГГ-ММ-ДД)`. Номера не переиспользуются.
3. Исходники и документацию обновляй в одной задаче: правило, числа, API, схему сохранений.
4. Баланс хранится в конфигурациях Luau; [balance.md](balance.md) — их представление. Независимых таблиц цен в UI нет.
5. Результаты проверок не пиши в документы систем. Обнови строку статуса в [verification.md](verification.md).
6. Предложения обозначай как планы и не включай в перечень работающих функций.
7. Документ не длиннее 15 000 символов. Перерос — сожми или раздели.
8. Манифесты в `assets/` — технический учёт файлов и Roblox ID, не спецификация.
