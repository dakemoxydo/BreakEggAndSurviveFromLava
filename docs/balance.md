## Формулы

**Доход одного активного животного в секунду:**

```text
max(1, floor(baseIncome(kind) × clamp(mass^0.7, 0.5, 10000)))
```

Общий Income — сумма доходов экипированных животных. След не умножает Cash. TestChick — совместимый старый вид с базовым доходом 5; он не является дополнительной записью текущего Index.

**Тренировка:** за каждую накопленную целую секунду `Speed += TrainingGain × trailMultiplier`. Подпись `/Step` в мире соответствует серверному секундному начислению; анимационные шаги не являются отдельными наградами.

**Передвижение:** в `Game.walkSpeed` передаётся `s = Speed × trailMultiplier`:

```text
Slow Mode: WalkSpeed = 16
Обычный режим: clamp(16 + ln(1 + max(0, s - 16)) × 4, 16, 96)
```

Таким образом, след влияет и на прирост Speed, и на передвижение. Число Speed в HUD не равно Humanoid.WalkSpeed.

**Merge:** `resultMass = (mass1 + mass2 + mass3) × 1.15`. Тип остаётся прежним.

**Сумка:** цена перехода с уровня `L` на `L+1` равна `1000 × 25^(L-1)`; уровень равен количеству полевых животных за заход. Максимум — 8.

**Загон:** после покупки `capacity = min(40, max(currentCapacity, 8 + (newPenLevel-1) × 4))`. Существующие дополнительные слоты не теряются. Уровни 1–9; цены следующих переходов: 100, 1500, 25000, 500000, 25000000, 1000000000, 50000000000000, 1000000000000000.

**Полевое вылупление:** масса равна `max(0.1, floor(scale^3 × random(0.7, 2.4) × 10) / 10)`.

**Размер питомца для всех видов и состояний:** `PetVisuals.petScale(kind, weight) = (speciesSize or 1) × max(weight, 0.1)^0.15`. Weight — масса в kg; больший вес внутри одного вида даёт больший размер без верхнего ограничения масштаба. Вылупившийся питомец, полевой груз, Tool инвентаря и модель базы используют это правило без дополнительных множителей переноса. Изменение массы при Merge создаёт новый размер результата. На экране масса отображается только при наведении на питомца на базе как «X kg».

scale в этой формуле — исходный размер полевого яйца. Анимационное увеличение оболочки ×1.65 не участвует в расчёте массы. Счётчик удачи растёт визуально от 0 до eggLuck; таблица eggLuck и распределение видов остаются прежними.

Поле `weight` в каталоге видов — вес случайного выбора, а не масса животного. Для обычного яйца выбор ограничен его биомом. Для i-го вида внутри биома:

```text
effectiveWeight_i = catalogWeight_i × max(0.5, eggLuck)^((i-1) × 0.45)
probability_i = effectiveWeight_i / sum(effectiveWeights)
```

Порядок видов влияет на распределение. Нельзя читать значение weight как готовый процент для любого яйца. Titanic выбирает TitanDragon напрямую.
