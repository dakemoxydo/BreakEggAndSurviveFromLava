Не синхронизировать Markdown в DataModel: `docs/` не входит в проекты Rojo.

Переиспользование компонентов не разрешает менять эти маршруты. После правки навигации выполнить минимальный сценарий проверки из ui.md.

## Запуск и сборка

Рабочая папка: `C:\Users\dakem\Documents\RobloxGames\BreakEggAndSurviveFromLava`. Нужны доступные команды Rojo и Wally; конкретные локальные версии инструментов здесь не зафиксированы. Зависимости перечислены в wally.toml и закреплены wally.lock. При отсутствии Packages выполнить `wally install`.

```powershell
rojo serve default.project.json --address 127.0.0.1
rojo build release.project.json -o BreakEggReference.rbxlx
rojo build bundle.project.json -o ShopUIBundle.rbxmx
```

В Studio подключить плагин Rojo к `127.0.0.1:34872`. Для работы с полной игрой открыть существующий полный place, затем подключить default-проект. Default не содержит карту: он обновляет скрипты, зависимости и модели кирок в уже существующем мире.

| Проект | Назначение |
|---|---|
| default.project.json | Исходники в текущей ручной сцене; сохраняет неизвестные объекты в указанных сервисах через ignoreUnknownInstances |
| release.project.json | Полный place: исходники, карта, шаблоны, освещение, материал, облака и Lava Bat |
| bundle.project.json | Отдельный UI-пакет; его дерево не включает всю серверную игру |

Успешная сборка подтверждает доступность указанных файлов и формирование артефакта. Она сама по себе не проверяет игровую логику, сетевые сценарии или покупки. Открытие полного экспортированного place следует проверять отдельно.

## Studio и сохранения

Для постоянных Studio-профилей требуется Enable Studio Access to API Services в настройках безопасности experience. По умолчанию StudioMode — Persistent; данные идут в отдельное Studio-хранилище. Для экспериментов можно явно выбрать Mock в `src/server/data/Config.luau` и синхронизировать Rojo. Mock не включается автоматически при ошибке API.

Перед проверкой через RobloxMCP получить список Studio и их режим, выбрать нужный place. Дерево Edit подходит для инспекции сцены и исходников; runtime-механики проверять в Server/Client после запуска Play. Останавливать Play и возвращать временные параметры событий после экспериментов. Для проверки ProfileStore использовать отдельный Mock-ключ из `tools/verify-profiles.luau`, не игровые ключи.

## Порядок изменения механики

1. Прочитать [gameplay.md](gameplay.md), [architecture.md](architecture.md) и соответствующий специализированный документ.
2. Изменить канонические файлы в src; численные параметры вынести в существующий конфиг, где это соответствует системе.
3. Обновить описание правил, таблицу [баланса](balance.md), [API](network-api.md) и схему сохранений при необходимости.
4. Синхронизировать Rojo, проверить результат через RobloxMCP и выполнить подходящие сценарии [verification.md](verification.md).
5. Для изменений карты обновить экспорт мира, если они должны попасть в release. Собрать нужный артефакт.
6. Записать фактически проведённые проверки, дату и ограничения. Не переносить старую формулировку «проверено» на изменённое поведение без повторной проверки.

Не переименовывать DataStore при обычном обновлении. Не переставлять каталог оборудования без учёта сохранённых индексов. Не менять стабильные ключи животных без миграции. Модели, Instance, Vector3 и CFrame не добавлять в Profile.Data.

## Карта и ассеты

Организация файлов описана в [assets/README.md](../assets/README.md). Для предмета хранить references, models, textures, icons и exports рядом. Roblox ID, источники и выбранные варианты фиксировать в манифестах, включая `assets/manifests/reference-assets.json` и каталог кирок.

В Studio каталог шаблонов находится в ServerStorage.Assets: Items/Pickaxes/{Templates,SourceImports}, Items/Bats, Items/Eggs, Environment/Treadmills, Environment/Props и Pets. Исходные импорты не оставлять выставленными в Workspace. Runtime-копии кирок в ReplicatedStorage.PickaxeModels обслуживают UI и выдачу Tool. Старый Assets.Weapons перенесён в Assets.Items.Bats; TreadmillLvl1 находится в Assets.Environment.Treadmills. Помощники place-treadmills и equip-imported-bat используют эти пути. Экспорт каталога AssetTemplates.rbxmx используется release; default продолжает синхронизировать исходники и рабочие PickaxeModels, сохраняя ручное серверное хранилище.

`tools/apply-reference-details.luau` предназначен для повторяемых правок оформления в Edit с резервной копией в ServerStorage.WorldBackups. Скрипты размещения и организации карты в tools — операции над сценой, а не обязательные шаги каждого запуска игры.

Экспортные помощники: `tools/export-world.luau`, `tools/snapshot-server.py`, `tools/build-world.py`. Они обновляют снимки геометрии, используемые release.project.json. Перед запуском прочитать конкретный скрипт и его пути; обновление только сцены Studio не меняет автоматически сохранённый экспорт карты. Обычная сборка release не требует запуска snapshot HTTP-сервера.

`tools/rojo-transfer.py` читает канонический XML из `.tools/reference-game.rbxlx` для MCP fallback при неприменившихся новых mappings. Это вспомогательный путь, не отдельный источник правды. Основной путь синхронизации остаётся Rojo.

## Публикация

Локальная сборка не означает публикацию. Дата и версия последнего опубликованного состояния здесь не подтверждены. Текущие Robux-предложения имеют ID=0; перед их включением нужны реальные продукты/пасы, серверная выдача и обработка чеков. Полный перечень непроверенного находится в [verification.md](verification.md).
