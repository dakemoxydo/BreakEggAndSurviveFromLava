# Модели и анимации питомцев: Blender → Roblox

Порядок создания импортированного питомца с анимациями. Образец — курица (`Chicken`): исходники в `assets/pets/`, скрипты в `tools/blender/`. Как модель используется в игре — [pets.md](pets.md).

## 1. Модель в Blender

- Стиль: low poly из блоков, фаска Bevel в 1 сегмент. Перед UV применить модификаторы.
- Перед питомца — `-Y`, верх — `+Z`, лапы стоят на `z = 0`. После экспорта перед в Roblox — `-Z`.
- Текстура studs/inlets — из `C:\Users\dakem\Documents\RobloxGames\Assets\Textures\HDStuds`. Inlets: `Inlets 2x2 AO Diffuse.png` + `Inlets 2x2 Normal.png`. Studs: `studs-2x2-*`. Вариант `Normal Plastic` даёт шум пластика.
- UV: кубическая проекция по координатам с одним масштабом для всех частей, тогда клетки везде одного размера. Сейчас — 2 клетки на метр.
- У `primitive_cube_add` есть свой слой `UVMap`. Его надо удалить или сделать активным свой слой (`active` + `active_render`), иначе текстура берёт не те UV.
- В Roblox у MeshPart одна текстура. Части объединяются по цвету (`ChickWhite`, `ChickOrange`…), и для каждого цвета запекается своя окрашенная текстура (`tools/blender/chick-inlets-textures.py`). Яркость рельефа задаёт `STRENGTH`. Он же ослабляет карту нормалей: Roblox не читает «силу» нормалей из Blender.
- После любой подмены текстуры проверить результат по пикселям: в центре клетки и в промежутке цвета должны различаться. Правки путей через `sed` с обратными слешами не срабатывали молча.

## 2. Скелет

- Один Armature, отдельный Root в начале координат. Каждая часть привязана к одной кости с весом 1.0, без автовесов: блоки двигаются жёстко.
- Кости — по подвижным частям: `Body`, `Head`, `Tail`, `WingL/R`, `LegL/R`. Ноги — дети Root, а не Body, чтобы подскок тела не отрывал лапы от земли.
- Ось вращения считается в локальных осях кости. У вертикальной кости `X` — шаг вперёд-назад. Направление проверять рендером: в первой версии крылья уходили в корпус, и знак поворота пришлось менять.
- Образец сборки: `tools/blender/rig-chick-v02.py`.

## 3. Анимации

- 60 fps. Последний кадр равен первому, чтобы цикл шёл без рывка. Ключ на каждом кадре.
- Каждое действие (Action) хранит свой диапазон кадров (`use_frame_range`), и у него `use_fake_user`, иначе Blender удалит неиспользуемое действие при сохранении.
- В Blender 5 у Action нет `fcurves`. Чтобы пересобрать действие, удалить его и создать заново.
- Амплитуды образца курицы: Walk — ноги 18°, крылья 14°, хвост 10°, тело ≤2°, голова ≤2.5°. Idle — до 6°. Корпус и голову двигать меньше конечностей.
- Просмотр: выделить Armature → Dope Sheet → Action Editor → выбрать действие → End = длина действия → Space в 3D-окне.

## 4. Экспорт FBX

- Модель: Armature + меши, текстуры вшиты в файл.
- Анимации: один файл со всеми действиями — только Armature, `bake_anim_use_all_actions=True`. Studio разбивает его на KeyframeSequence `ChickRig|Idle`, `ChickRig|Walk`. Отдельный файл на анимацию не нужен.
- Настройки: `apply_unit_scale=True`, `FBX_SCALE_UNITS`, forward `-Z`, up `Y`, `add_leaf_bones=False`, `bake_anim_force_startend_keying=True`, `bake_anim_simplify_factor=0`.

## 5. Импорт в Studio

1. Import 3D → модель, Rig Type Custom. Импортёр создаёт RootPart с костями, MeshPart со SurfaceAppearance, включая карту нормалей, и AnimationController с Animator.
2. Animation Editor → выбрать модель → Import → From FBX Animation → файл анимаций.
3. Сохранения анимаций (`ServerStorage.RBX_ANIMSAVES.<имя модели>`) привязаны к модели, в которую импортировали. Load видит только сохранения выбранной модели: чтобы смотреть их на другой модели, KeyframeSequence копируют в её папку.
4. **Обязательно** выполнить `tools/fix-bone-pose-rest.luau` для новых KeyframeSequence. Импорт записывает в позы костей полный поворот (исходный поворот кости × изменение), а Animator применяет позу поверх исходного поворота кости. Кости, повёрнутые в покое (ноги и крылья вниз, наклонный хвост), разворачиваются дважды: крылья смотрят вверх, ноги уходят внутрь. Превью Animation Editor этого не показывает, ошибка видна только в Play.
5. Проверить в Edit без Play: `KeyframeSequenceProvider:RegisterKeyframeSequence` + `Animator:StepAnimations` на клоне шаблона и сравнить углы `Bone.Transform` с Blender. Клон удалить.
6. ПКМ по KeyframeSequence → Save to Roblox. При исправлении перезаписывать прежнюю анимацию: AnimationId не меняется. Публиковать с того аккаунта или группы, которым принадлежит игра.

## 6. Шаблон и подключение

- Шаблон: `ServerStorage.Assets.Pets.<key>` (TestChick использует Chicken). Убрать `InitialPoses` и `AnimSaves`. Части сделать Anchored, без CanCollide, CanTouch и CanQuery, Massless.
- RootPart перенести в центр тела, сохранив положение мешей: C0 моторов и `Root.CFrame` умножаются на обратный сдвиг. Затем `PivotOffset` вернуть на лапы. Хват Tool и подписи рассчитаны на центральный PrimaryPart.
- Папка `Animations` с Animation `Idle` и `Walk`. Код играет оба клипа зацикленно на клиенте и смешивает их по `PetWalking`.
- Подвижные модели (питомцы базы) сервер не двигает через `PivotTo`: он задаёт `PetPosition`, `PetYaw`, `PetWalking`, а клиент сглаживает движение. Иначе модель двигается рывками и без анимаций.
- Шаблон живёт только в place (`ServerStorage.Assets.Pets`). Без шаблона используется процедурная модель.
- Импортированная модель несёт служебный атрибут `RBX_ReimportId`. Скрипт не может его снять (нужны права CoreScript): при очистке атрибутов клона пропускать имена `RBX_*`, иначе код падает.

## 7. Проверка перед «готово»

- Рендер в Blender: стоит, середина шага, взмах — спереди и сбоку.
- Studio Edit: дерево шаблона, pivot на лапах, углы Bone.Transform.
- Play у пользователя: поле, база, рука, перенос над головой, Index, Output без ошибок.
